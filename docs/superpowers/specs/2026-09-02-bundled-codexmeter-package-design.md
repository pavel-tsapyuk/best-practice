# Включение CodexMeter в пакет Best Practice

Дата: 2026-09-02
Статус: утверждено пользователем

## Цель

Пользователь должен иметь возможность на любом своём Windows-компьютере получить актуальный установщик CodexMeter только из приватного репозитория `best-practice`, не клонируя отдельно приватный репозиторий CodexMeter.

## Выбранный подход

Best Practice хранит одну актуальную проверенную сборку CodexMeter непосредственно в каталоге `packages/CodexMeter`:

```text
packages/CodexMeter/
├── CodexMeter-Setup.exe
├── CodexMeter-Setup.exe.sha256
├── VERSION
└── INSTALL.md
```

Текущей включаемой версией является CodexMeter `1.1.1` из тега `v1.1.1`, commit `804d30d8f77a5f9addd2db3c2156b0c832e2a585`. Ожидаемый SHA-256 установщика:

```text
2AE0BF6815ABC50E100EA7852E3556F6A96AAB105DEE971FC557D6F1C707064E
```

В репозитории хранится только текущий установщик; предыдущие варианты остаются доступны через историю Git. Это устраняет зависимость от доступа второго компьютера к отдельному репозиторию CodexMeter и не вводит плавающую загрузку с `main`.

## Пользовательский сценарий

На компьютере с существующим клоном Best Practice пользователь запускает fail-closed сценарий: `git pull --ff-only` проверяется по коду завершения, корень клона определяется через `git rev-parse --show-toplevel`, после чего выполняются переход в `packages/CodexMeter` и проверка SHA-256. Установка и `/quiet /whatif` запускаются через `Start-Process -Wait -PassThru`, поэтому код завершения принадлежит завершившемуся GUI bootstrapper, а не предыдущей команде PowerShell.

Тот же установщик поддерживает первую установку и обновление. Режим `/quiet /whatif` проверяет совместимость и содержимое без установки. Установщик остаётся неподписанным, поэтому инструкция заранее объясняет возможное предупреждение Windows SmartScreen.

## Обновление пакета

При выпуске новой стабильной версии CodexMeter сопровождающий обязан одной транзакцией:

1. взять `CodexMeter-Setup.exe` из проверенного тега/релизного commit CodexMeter;
2. заменить установщик;
3. заменить `CodexMeter-Setup.exe.sha256`;
4. обновить `packages/CodexMeter/VERSION`;
5. обновить сведения о версии в `INSTALL.md` и записи Best Practice;
6. пройти контракт пакета и проверку чистого клона.

Версия Best Practice повышается на patch, поскольку меняется поставляемое проектное применение, но не общее активное ядро.

## Безопасность и границы данных

В Best Practice не переносятся `codex.exe`, данные учётной записи, токены, логи, ответы локального app-server, реестр или машинные пути. Bootstrapper содержит только утверждённый payload CodexMeter. На целевом компьютере он находит локальную официальную установку Codex и работает с учётной записью пользователя, который вошёл в Codex на этом компьютере.

SHA-256 защищает от повреждения и случайной рассинхронизации файлов. Доверие к самому бинарнику обеспечивается приватным репозиторием Best Practice и проверяемым происхождением от точного релиза CodexMeter; цифровой подписи пока нет.

## Проверки

Автоматический контракт должен проверять:

- наличие всех четырёх файлов пакета;
- точное соответствие SHA-256 фактическому `CodexMeter-Setup.exe`;
- совпадение версии пакета с заявленной в документации;
- допустимый Windows GUI PE-файл и отсутствие машинных данных или секретов в текстовых файлах;
- fail-closed порядок обновления/поиска корня и синхронные команды установки и `/quiet /whatif` в `INSTALL.md` и проектной инструкции;
- то, что `packages` и `packages/CodexMeter` являются настоящими контейнерами, а не reparse points, до перечисления дочерних элементов;
- строгий UTF-8 без BOM для всех затронутых release text files;
- получение пакета из свежего клона Best Practice с неизменившимся SHA-256.

Финальная проверка включает запуск bootstrapper в `/quiet /whatif` из изолированного свежего клона только через `Start-Process -Wait -PassThru`, а затем сравнение SHA-256 установленного EXE, точного набора PID и HKCU Run value после завершения процесса. Реальная установка поверх действующего виджета не выполняется без отдельной необходимости: она уже относится к состоянию компьютера, а не к целостности переносимого пакета.

## Не входит в задачу

- публикация CodexMeter в открытом репозитории;
- создание сертификата или подписание установщика;
- хранение нескольких версий одновременно;
- изменение исходников или поведения CodexMeter;
- автоматическая загрузка бинарника из внешнего репозитория при каждом использовании Best Practice.
