# Monitored Sources

```yaml
scope: shared
stability: verify-current
conflict: ask
```

Внешний источник создаёт кандидатов для проверки, а не активные правила. Новость, рекламное заявление, число подписчиков, цена, лимит, benchmark или список возможностей считаются изменчивыми до сверки с первичным источником.

## Решения по просмотру 2026-09-13

Принято в общую базу:

- аудит prompts, `AGENTS.md` и skills после смены модели или harness;
- A/B-проверка skills/plugins относительно baseline без расширения;
- предметная компетентность human reviewer;
- внедрение AI через внутреннего владельца процесса и один узкий пилот;
- разделение авторского решения и механического сбора/проверки контента;
- расширенная защита секретов и изоляция browser automation;
- append-only журнал событий для восстанавливаемого agent harness;
- стабильный prompt-cache prefix и экспериментальный выбор effort;
- ограниченная маршрутизация механической работы на дешёвую модель.

Принято только как проектные кандидаты или Tool Radar:

- локальная запись и транскрибация;
- Битрикс24 Коворк/Код и Радиант;
- Apache Maka, tgrep, ui-skills, screenshot-to-code, Unity Agent Plugin;
- NVIDIA Personal AI Router и Model Hardware Standard;
- курсы CMU 11-768 и Stanford CS329Z.

Отклонено:

- недокументированный `features.context_management.experimental_mode` — нет подтверждения в официальной документации Codex;
- `codex-chatgpt-web` для обхода лимитов через авторизованную веб-сессию — риск учётных данных, условий сервиса и неподтверждённой обвязки;
- тезис, что работающий сгенерированный код необязательно понимать человеку, — противоречит ответственности, поддерживаемости и независимой проверке;
- предложение считать падение production приемлемой частью обучения AI-амбассадора — пилоты должны быть изолированы от production.

## Процедура отбора

1. Зафиксировать источник, дату и просмотренный диапазон.
2. Удалить рекламу, мемы, повторы и сведения без практического действия.
3. Отделить устойчивый принцип от продуктовой новости.
4. Сверить изменчивое утверждение с первичным источником.
5. Проверить, нет ли идеи уже в базе.
6. Присвоить `scope`, `stability` и `conflict`.
7. Предложить одно действие: добавить в базу, проверить экспериментом, применить в проекте или отклонить.
8. Не активировать новое общее правило автоматически.

## Формат отчёта

Для каждой находки сообщать:

1. краткое резюме;
2. практическую пользу;
3. риски и ограничения;
4. первичный источник;
5. метки валидности;
6. рекомендуемое действие;
7. итоговое решение пользователя.
