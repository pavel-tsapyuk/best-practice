# Обмен полезными находками между установками

## Выпуск 2026-10-04 — Best Practice 2.4.1

```yaml
scope: shared
stability: verify-current
conflict: preserve-local
```

Назначение: передать результаты обзора внешних источников и применимые практики другим машинам. Пользователь поручил сохранить всё полезное и передать в Computers команду забрать и применить материалы. Это разрешение на получение справочной базы и применение уместных практик, а не на безусловную установку всех перечисленных продуктов.

### Шесть приоритетов для наших задач

1. **OpenViking — поиск и очистка базы знаний.** Пилот на копии корпуса: сравнить с текущим файловым поиском по полноте, точности и времени; изменения памяти сначала показывать как diff.
2. **Langfuse — качество агентов на реальных ошибках.** Составить небольшой набор обезличенных случаев и оценивать ответы вместе с действиями инструментов. Подключение телеметрии — отдельная интеграция.
3. **BrowserSkill — работа с авторизованным Б24.** Сначала сравнить с уже доступным браузером и коннекторами. При необходимости проверить права расширения и провести ограниченный пилот чтения; новый доступ к учётной записи не выдавать автоматически.
4. **Проверка побочных последствий.** В релевантном review проверять повторные запросы, дубли уведомлений, идемпотентность, гонки, частичные сбои и откат. Отдельный агент нужен только при пользе для задачи; встроенный плагин Claude не требуется.
5. **Конвейер коротких видео.** На собственных записях: расшифровка → фрагменты с таймкодами → монтаж → оформление → проверка синхрона → человеческая приёмка. Для первого опыта достаточно одной демонстрации АРМ.
6. **Agents API — помощник по Б24 и документам.** Кандидат для узкого пилота с измеримым результатом; сначала чтение и подготовка черновиков, запись через существующие разрешения и подтверждения. Проверить стоимость, хранение данных и доступность.

### Применение на другой машине

1. Получить опубликованный commit выпуска, проверить diff и прочитать этот файл вместе с `memory/VALIDITY.md`. Сохранить незакоммиченные изменения; не использовать reset/clean для синхронизации.
2. Принять этот файл как справочный материал. Уместные практики review и проверки качества применять в рамках уже разрешённых задач. Отметить наличие материалов отдельно от фактически внедрённых интеграций.
3. Сохранять локальные AGENTS.md, LOCAL OVERRIDES, MCP, plugins, permissions, paths, уведомления, модели/reasoning/скорость и действующий October Full Throttle. Выпуск не содержит изменений ядра или конфигурации. Не применять старый экономичный профиль из 2.4.0 как часть этого обновления.
4. Для каждого из шести приоритетов выбрать статус: «применено как практика», «уже покрыто имеющимися средствами», «пилот предложен», «не применимо» или «заблокировано». Не выдавать скачанный справочник за установленный инструмент.
5. Новые установки, доступы, платные сервисы, передача рабочих данных и изменения других репозиториев требуют своего контекста и разрешения. При конфликте сохранять локальное значение. Повторно не спрашивать разрешение на уже порученное получение справочной базы.
6. Ответить в Computers: машина, версия/commit полученной базы, применённые практики, проверки, сохранённые настройки и оставшиеся пилоты. Не объявлять все компоненты синхронизации applied только потому, что этот файл получен.

Решение пользователя: сохранить полезные материалы и передать другим машинам для применения. Пилоты и продуктовые внедрения остаются условными до проверки применимости.
