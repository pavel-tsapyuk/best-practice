# FlClashX на Windows: подключение через Германию

```yaml
scope: project
stability: verify-current
conflict: ask
```

Справочная процедура для Windows. Проверена 2026-11-09 на одной установке Windows x64 с FlClashX 0.4.2. На другом компьютере проверь версию клиента, пункты меню и результат запроса. Для подключения нужна действующая подписка с немецким узлом.

## Подключение

1. Скачай установщик своей архитектуры из [официального релиза FlClashX](https://github.com/pluralplay/FlClashX/releases/tag/v0.4.2). Сверь SHA-256 с соседним файлом `.sha256`. Установи приложение и добавь свою подписку на вкладке **Профили**. Ссылку на подписку храни локально.
2. Для браузера, который использует настройки Windows, открой **Настройки → Конфигурация ядра → Сеть**. Включи **Системный прокси** и выключи **TUN**, если нужен только этот сценарий. Перед переключением учти действующий системный прокси и VPN машины.
3. На **Главной** выбери **Глобальный**. В разделе **Прокси** раскрой **GLOBAL** и выбери **Германия** или нужный немецкий узел из своей подписки. Выбранный узел должен появиться под заголовком **GLOBAL**.
4. На **Главной** нажми **▶**. Дождись зелёного статуса **Запущено** и проверь выход по процедуре ниже.

## Сигналы готовности

| Сигнал | Что подтверждает |
|---|---|
| **GLOBAL → Германия** | Выбран немецкий узел. Если видны только `DIRECT` и `REJECT`, узлы профиля не загрузились. |
| **Запущено** и таймер | FlClashX включил подключение. Страну выхода проверяет внешний запрос. |
| Windows выбирает локальный HTTP-прокси для тестового HTTPS-адреса | Системная маршрутизация на тестовый адрес настроена. На проверенной машине использовался `127.0.0.1:7890`. |
| Внешний запрос через этот прокси отвечает `HTTP 200` и `loc=DE` | Немецкий выход подтверждён для проверенного маршрута. |

Проверка в PowerShell выводит статус, страну и локальный адрес прокси. Публичный IP в вывод не попадает. Источник поля `loc` — [Cloudflare Trace](https://developers.cloudflare.com/fundamentals/reference/cdn-cgi-endpoint/).

```powershell
$ErrorActionPreference = 'Stop'
$target = [uri]'https://www.cloudflare.com/cdn-cgi/trace'
$proxy = [System.Net.WebRequest]::GetSystemWebProxy().GetProxy($target)
if ($proxy.Host -ne '127.0.0.1' -or $proxy.Scheme -ne 'http') {
    throw 'Windows did not select the local HTTP proxy for the test URL.'
}
$result = Invoke-WebRequest -UseBasicParsing -Uri $target -Proxy $proxy -TimeoutSec 15
$country = [regex]::Match($result.Content, '(?m)^loc=([A-Z]{2})\r?$').Groups[1].Value
if ($result.StatusCode -ne 200 -or $country -ne 'DE') {
    throw "Germany exit not verified. HTTP=$($result.StatusCode), loc=$country"
}
"READY: HTTPS 200, exit country DE, proxy $($proxy.Authority)"
```

Считай подключение готовым после `READY`. Если нужен конкретный браузер, открой в нём [Cloudflare Trace](https://www.cloudflare.com/cdn-cgi/trace) и проверь `loc=DE`. Это отдельно подтверждает маршрут браузера, в том числе если он задаёт собственный прокси.

## Если видны только DIRECT и REJECT

Сначала проверь, что профиль выбран, обновляется и содержит прокси. На проверенной машине одновременно наблюдались `getConfig timed out`, атрибут EFS у YAML-профиля и запущенная служба `FlClashHelperService` под `LocalSystem`. Ядро читало тот же файл при запуске от вошедшего пользователя. Это позволило связать сбой с доступом служебной учётной записи к зашифрованному файлу. См. [описание EFS](https://learn.microsoft.com/en-us/windows/win32/fileio/file-encryption) и [выбор способа запуска ядра в FlClashX 0.4.2](https://github.com/pluralplay/FlClashX/blob/v0.4.2/lib/clash/service.dart).

Если признаки совпали и нужен системный прокси, останови подключение и закрой FlClashX. В оснастке **Службы** с правами администратора останови только `FlClashHelperService`. Открой FlClashX от вошедшего пользователя с выключенным TUN. Убедись, что в **GLOBAL** появились узлы, выбери Германию и повтори проверку готовности. Так на проверенной машине подписка осталась зашифрованной и запрос вернул `loc=DE`.

Остановка службы действует до её следующего запуска. Если у службы тип запуска **Автоматически**, после перезагрузки ошибка может вернуться. Сохранение настройки после перезагрузки в этой проверке не подтверждалось. Чтобы завершить сеанс прокси, нажми кнопку остановки на **Главной**.
