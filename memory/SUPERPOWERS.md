# Using superpowers

```yaml
scope: shared
stability: stable
conflict: enforce-shared
```

Этот файл раскрывает обязательное правило из `AGENTS_CORE.md`; при синхронизации активным остаётся короткая формулировка ядра.

## Статус

**Обязательное правило.**

Using superpowers должно быть первым содержательным шагом перед нетривиальной работой Codex, если в среде доступны соответствующие skills/superpowers.

## Правило

Перед реализацией:
1. Определи тип задачи.
2. Проверь доступные skills/superpowers.
3. Выбери наиболее подходящий.
4. Примени его инструкции.
5. Только после этого переходи к самостоятельной реализации.

Особенно искать superpowers/skills для:
- анализа репозитория;
- планирования;
- отладки;
- тестирования;
- code review;
- рефакторинга;
- работы с документацией;
- UI/UX;
- Git/GitHub;
- миграций и инфраструктуры.

Если ни один skill не подходит, это не блокирует работу. Продолжай обычным инженерным процессом.

## Аудит набора skills

Обязательность Using Superpowers не означает, что нужно загружать каждый доступный skill.

- Держать descriptions короткими и точно описывать момент срабатывания.
- Не использовать формулировки, из-за которых узкий skill вызывается для всей широкой предметной области.
- Для большого skill применять progressive disclosure: корневой файл маршрутизирует к нужной инструкции, а не загружает всё сразу.
- Удалять дубли и устаревшие model-specific костыли после проверки на реальных задачах.
- После заметной смены модели или среды повторять аудит, но не ослаблять правила безопасности и обязательную проверку результата без явного решения пользователя.
- Для важного skill сравнивать несколько прогонов с ним и без него; высокая оценка без положительной разницы относительно baseline не доказывает пользу skill.

Основание: [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) и [Test plugins with evals](https://code.claude.com/docs/en/plugin-evals).

## Антипаттерны

Нельзя:
- пропускать шаг только потому, что задача «кажется знакомой»;
- формально упоминать superpowers, но не применять их инструкции;
- выбирать skill по названию, не проверив область применения;
- использовать skill вопреки более конкретному `AGENTS.md` проекта.
- устанавливать или сохранять дублирующий skill без проверки, какую уникальную функцию он добавляет.

## Цель

Superpowers нужны не ради церемонии, а чтобы Codex использовал проверенный рабочий процесс вместо случайной импровизации.
