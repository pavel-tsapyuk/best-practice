# AGENTS.md — Shared Codex Rules

Этот файл задаёт общие правила работы Codex во всех проектах пользователя, если локальный проектный `AGENTS.md` не задаёт более конкретные правила.

## 1. Обязательный старт: Using superpowers

**Using superpowers — обязательный шаг перед содержательной работой.**

Перед выполнением нетривиальной задачи:
1. Проверь, какие доступные skills/superpowers применимы к задаче.
2. Используй подходящий skill/superpower до начала импровизационной реализации.
3. Если доступен skill, покрывающий задачу, не обходи его без причины.
4. Если подходящего skill нет, явно переходи к обычному рабочему процессу.
5. Для разработки сначала используй суперспособности/skills для анализа, планирования, тестирования, отладки и проверки, когда они доступны.
6. Не считай использование superpowers декоративным ритуалом: они должны реально влиять на план и проверки результата.

Подробнее: `memory/SUPERPOWERS.md`.

## 2. Сначала задача, потом код

Перед изменением кода:
- сформулируй наблюдаемый результат;
- зафиксируй критерии готовности;
- определи границы файлов/компонентов;
- определи, что менять нельзя;
- найди существующие тесты/проверки;
- при неоднозначности запрашивай данные, а не галлюцинируй.

Для сложной задачи сначала составь план. Для простой не раздувай процесс.

## 3. Harness Engineering

Качество работы агента определяется не «магическим промптом», а harness:
- контекст;
- правила;
- примеры;
- права и ограничения;
- тесты;
- критерии успеха;
- песочницы;
- наблюдаемость;
- управляемая память.

Промпт воспринимай как современное ТЗ.

## 4. BDD / criteria of done

По возможности описывай задачу через наблюдаемое поведение:
- Given / When / Then или эквивалент;
- конкретные входы;
- конкретные ожидаемые выходы;
- ошибки и граничные случаи.

Нельзя считать задачу выполненной только потому, что код выглядит правдоподобно.

## 5. Минимальная достаточная сложность

- Если достаточно обычной функции/SQL/API/правила — не используй LLM.
- Если достаточно детерминированного workflow с LLM-вызовом — не строй агента.
- Если справляется один агент — не строй мультиагентную систему.
- Агент оправдан только при реальной необходимости самостоятельно выбирать действия, инструменты или маршрут в условиях неопределённости.

## 6. Human-in-the-loop

Для новых автоматизаций:
- сначала человек подтверждает результат;
- проведи серию тестов;
- измеряй качество, ошибки, время, токены и стоимость;
- уменьшай человеческий контроль только после устойчивой статистики.

Ориентиры из сохранённых материалов:
- около 20 тестовых прогонов перед выводами о стабильности;
- >80% результатов без ручных исправлений может быть сигналом к уменьшению контроля.
Это эвристики, не универсальные SLA.

## 7. Инженерия вместо театра ИИ

Не поручай LLM:
- точную арифметику;
- строгие сравнения;
- сортировку;
- формальные бизнес-правила;
- то, что надёжно решается обычным кодом.

LLM используй для:
- понимания неструктурированного текста;
- классификации с неопределённостью;
- извлечения сущностей;
- анализа визуального контента;
- генерации черновиков;
- выбора из неформализованного пространства действий, если это действительно нужно.

## 8. Стоимость и эксплуатация

Open source не считать бесплатным автоматически. Учитывай:
- VPS;
- GPU;
- хранилище;
- API;
- модели;
- резервирование;
- обновления;
- администрирование;
- наблюдаемость;
- время поддержки.

Если автоматизация дороже ручной операции, сначала сузь задачу или упрости архитектуру.

## 9. Память проекта

Разделяй:
- задачи;
- постоянный контекст;
- инструкции;
- решения;
- ретроспективу.

Не переписывай автоматически фундаментальные правила проекта без явного основания.

## 10. Безопасность

Секреты, токены, webhook URL и API-ключи не должны попадать в Git.
Для новых проектов рассматривать Infisical или эквивалентное безопасное хранилище секретов.
Никогда не коммить `.env` с реальными секретами.

## 11. Проверка результата

После изменений:
- запусти релевантные тесты;
- проверь линтер/типизацию/сборку, если применимо;
- проверь поведение на реальном сценарии;
- перечисли оставшиеся риски;
- не скрывай непроверенные предположения.

## 12. Радар знаний

При выборе архитектуры и инструментов сверяйся с:
- `memory/PRINCIPLES.md`;
- `memory/TOOLS.md`;
- `memory/PATTERNS.md`;
- `memory/PROJECT_APPLICATIONS.md`.

Не внедряй инструмент только потому, что он присутствует в радаре.
